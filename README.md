# Business Plan 120k Report

สกิลสำหรับ **Codex** ที่ช่วยสร้าง ตรวจ และปรับรายงานแผนธุรกิจภาษาไทย โดยเชื่อมไอเดีย ลูกค้า ตลาด ทีม แผนงาน งบประมาณ และการเงินเข้าด้วยกัน พร้อมบอกว่าข้อสรุปไหนมีหลักฐาน ข้อไหนเป็นสมมติฐาน และอะไรยังต้องพิสูจน์

ชื่อที่ใช้เรียกคือ `$bussiness-plan-120kreport` — `120kreport` เป็นชื่อสกิล ไม่ได้กำหนดให้ทุกธุรกิจใช้งบ 120,000 บาท

## มีไว้ทำอะไร

- **เริ่มจากไอเดีย:** วิเคราะห์ธุรกิจ ถามข้อมูลที่มีผลต่อแผน และสร้างดราฟที่นำไปพัฒนาต่อหรือเตรียมส่งได้
- **ตรวจดราฟที่มีแล้ว:** หาจุดที่เหตุผลไม่เชื่อมกัน ตัวเลขขัดกัน หลักฐานไม่พอ หรือยอดขายเกินกำลังทีม
- **แก้ตาม feedback หรือ rubric:** ปรับส่วนที่เกี่ยวข้องและตรวจผลกระทบต่อส่วนอื่นของรายงาน
- **ตรวจรอบสุดท้าย:** ตรวจภาษา ตัวเลข แหล่งอ้างอิง และความพร้อมส่ง โดยรักษาสาระที่ตกลงแล้ว

สกิลช่วยอธิบายว่า **จะใช้เงินเท่าไร ใช้ทำอะไร และสมเหตุสมผลอย่างไร** โดยไม่ใส่คำขอรับทุนเป็นค่าเริ่มต้น หากมี rubric จะจัดเนื้อหาให้ครอบคลุมเกณฑ์ แต่ไม่รับรองคะแนนหรือความสำเร็จของธุรกิจ

## ปรับตามธุรกิจอย่างไร

ก่อนเลือกวิธีวิเคราะห์ สกิลจะสร้าง **Business Fingerprint**: ใครใช้ ใครจ่าย ลูกค้าซื้ออะไร รายได้มาจากไหน ต้นทุนขับเคลื่อนด้วยอะไร ทีมมีกำลังเท่าไร ธุรกิจอยู่ระยะไหน และมีหลักฐานพร้อมเพียงใด

จึงใช้ได้กับหลายบริบท เช่น ร้านอาหาร สินค้า บริการ โรงงาน software หรือธุรกิจผสม โดยเลือกตัวชี้วัดและแบบจำลองการเงินตามธุรกิจจริง ไม่บังคับให้ทุกธุรกิจใช้ CAC, subscription หรือวิธีคิดแบบ SaaS

มี **PostFlow Business Plan ฉบับ 2.11 เต็มฉบับ** เป็นตัวอย่างระดับคุณภาพการเขียนและการเชื่อมเหตุผล สกิลไม่ใช้ตัวเลข งบ ราคา ทีม หรือสมมติฐานของ PostFlow เป็นค่าเริ่มต้นของธุรกิจใหม่

## สิ่งที่จะได้

เมื่อสร้างรายงานใหม่ จะได้สองไฟล์:

| ไฟล์ | เนื้อหา |
|---|---|
| `<ชื่อธุรกิจ>-Business-Plan-Draft.md` | รายงานหลักสำหรับอ่านและนำไปใช้ต่อ |
| `<ชื่อธุรกิจ>-Evidence-and-Decisions.md` | ที่มาของหลักฐาน สมมติฐาน สูตรคำนวณ เหตุผลการตัดสินใจ และสิ่งที่ยังต้องทดสอบ |

รายงานหลักรักษาลำดับ 10 หัวข้อ:

1. บทสรุปผู้บริหาร
2. ภาพรวมธุรกิจ
3. การวิเคราะห์ธุรกิจและตลาด
4. แผนการบริหารจัดการองค์กร
5. ผลิตภัณฑ์และกระบวนการให้บริการ
6. แผนการตลาดและแผนการขาย
7. แผนงบประมาณโครงการ
8. แผนรายได้และความเป็นไปได้ทางการเงิน
9. เกณฑ์ตัดสินใจและแผนรับมือ
10. ภาคผนวกและเอกสารอ้างอิง

ปรับหัวข้อย่อยและรายละเอียดตามธุรกิจได้ หาก rubric บังคับโครงต่างออกไป สกิลจะอธิบายความแตกต่างและปรับตามข้อกำหนดของงาน

## วิธีติดตั้ง

1. [ดาวน์โหลด ZIP ของสกิล](https://raw.githubusercontent.com/uhactuallyidk/bussiness-plan-120kreport/main/bussiness-plan-120kreport.zip)
2. แตกไฟล์ แล้วนำโฟลเดอร์ `bussiness-plan-120kreport` ไปไว้ในโฟลเดอร์ skills ของ Codex:
   - Windows: `%USERPROFILE%\.codex\skills\`
   - macOS / Linux: `~/.codex/skills/`
   - หากตั้ง `CODEX_HOME` เอง ให้ใช้โฟลเดอร์ `skills` ภายในตำแหน่งนั้น
3. ตรวจว่า `SKILL.md` อยู่ใต้โฟลเดอร์สกิลโดยตรง ไม่ซ้อนชื่อโฟลเดอร์อีกชั้น แล้วเปิด Codex ใหม่หากยังไม่เห็นสกิล

ตัวอย่างตำแหน่งบน Windows:

```text
C:\Users\<ชื่อผู้ใช้>\.codex\skills\bussiness-plan-120kreport\SKILL.md
```

ชุดสกิลมี 3 ไฟล์ ส่วน README นี้เป็นเอกสารอธิบายที่หน้า repository ไม่ต้องคัดลอกเข้าโฟลเดอร์สกิล

## วิธีใช้

เปิด workspace ที่เก็บเอกสารของธุรกิจ แนบหรือระบุไฟล์ที่เกี่ยวข้อง แล้วเรียกชื่อสกิลพร้อมงานที่ต้องการ เช่น:

**สร้างรายงานใหม่ — Build**

```text
$bussiness-plan-120kreport ช่วยสร้างแผนธุรกิจสำหรับร้านอาหารของทีมเรา
ใช้ข้อมูลและ rubric ใน workspace นี้ ตอนนี้อยู่ระยะทดลองขาย มีทีม 3 คน
เริ่มจากวิเคราะห์บริบท ถามข้อมูลที่จำเป็น แล้วสร้างรายงานกับบันทึกหลักฐาน
```

**ตรวจดราฟ — Audit**

```text
$bussiness-plan-120kreport ตรวจดราฟนี้ด้านเหตุผล หลักฐาน งบ และกำลังทีม
บันทึกข้อค้นพบกับข้อเสนอ โดยยังไม่เขียนทับรายงานหลัก
```

**แก้ตาม feedback — Repair**

```text
$bussiness-plan-120kreport แก้งบโครงการเป็น 75,000 บาทตาม feedback นี้
ตรวจสูตรและส่วนของรายงานที่ได้รับผลกระทบ พร้อมอัปเดตบันทึกการตัดสินใจ
```

**ตรวจพร้อมส่ง — Final Review**

```text
$bussiness-plan-120kreport ตรวจรายงานรอบสุดท้ายก่อนส่ง
รักษาโครงและสาระที่ตกลงแล้ว ตรวจความสอดคล้อง ตัวเลข citations และรูปแบบ
เปิดแก้สาระเฉพาะเมื่อพบข้อผิดพลาดสำคัญ
```

ข้อมูลที่ช่วยให้ทำงานได้ดีขึ้นคือ stage ของธุรกิจ ผู้ใช้/ผู้จ่าย สิ่งที่ขาย ราคา ต้นทุน ทีมและเวลาที่ทำได้ ผลทดลองที่มี รวมถึง rubric วงเงิน และระยะเวลาที่งานกำหนด ไม่จำเป็นต้องมีข้อมูลครบก่อนเริ่ม

## เมื่อหลักฐานยังไม่ครบ

สกิลจะแยกข้อมูลที่ทีมยืนยัน ผลวัดจริง ข้อมูลภายนอก สมมติฐาน และเป้าหมายออกจากกัน หากต้อง research เพิ่มจะแจ้งสิ่งที่จะค้น และบันทึกแหล่งที่ใช้จริง

ผลใช้จริง เช่น เวลาที่ประหยัดได้ การชำระเงิน หรือการกลับมาใช้ซ้ำ ต้องมาจากข้อมูลของทีม สกิลจะไม่ใช้ข้อมูลตลาดแทนผลเหล่านี้ แต่จะระบุสิ่งที่ยังไม่ทราบและเสนอวิธีเก็บหลักฐาน หากยังไม่มีฐานสำหรับ TAM/SAM/SOM สามารถใช้ Market Context พร้อมแผนพิสูจน์ตลาดได้

เมื่อแก้ประเด็นสำคัญจากข้อมูลปัจจุบันครบแล้ว สกิลจะประกาศ content freeze เพื่อจำกัดการแก้รอบต่อไป การ freeze เอกสารไม่ได้หมายความว่าธุรกิจผ่านการพิสูจน์แล้ว

## โมเดลและขอบเขต

แนะนำใช้ `gpt-6.1-sol` สกิลไม่เปลี่ยนโมเดลให้เอง และค่าเริ่มต้นไม่หยุดงานเพียงเพราะตรวจชื่อโมเดลไม่ได้

สกิลนี้ออกแบบสำหรับงานแผนธุรกิจและการตรวจแก้เนื้อหาที่เกี่ยวข้อง งานตั้งชื่อ แปลข้อความ หรือคำนวณสั้น ๆ ไม่จำเป็นต้องเปิดกระบวนการเต็ม ทั้งนี้ reference เก็บลิงก์ภาพจากต้นฉบับไว้ แต่ ZIP ไม่ได้รวมไฟล์ภาพจากเครื่องผู้สร้าง
